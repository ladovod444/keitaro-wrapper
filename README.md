# Keitaro Wrapper

Полноценное Fullstack-приложение для управления рекламными кампаниями в трекере Keitaro. Позволяет быстро создавать кампании со стандартной двухпоточной логикой и удобно управлять офферами в существующих кампаниях.

## 🛠 Технологический стек

**Backend:**
- Python 3.10+
- FastAPI (асинхронный веб-фреймворк)
- SQLAlchemy 2.0 + aiosqlite (асинхронная работа с локальной БД)
- Pydantic V2 (валидация данных и управление настройками)
- HTTPX (асинхронные запросы к Keitaro Admin API)

**Frontend:**
- React 18 + Vite
- Tailwind CSS (стилизация и адаптивная верстка)
- Axios (HTTP-клиент для взаимодействия с Backend)

**Тестирование:**
- Pytest + FastAPI TestClient
- Monkeypatch (мокирование внешних API для детерминированных и быстрых тестов)

---

## ✨ Ключевые возможности

1. **Создание кампаний:** Генерация кампании с двумя потоками:
   - Поток 1: Редирект на внешний URL с фильтром по стране (`geo_code`).
   - Поток 2: Распределение трафика на целевой оффер (ловит весь остальной трафик).
2. **Редактирование офферов:** Удобный интерфейс для добавления и удаления офферов с **автоматическим расчетом `share`** (защита от превышения 100% и валидация ввода).
3. **Управление настройками:** Хранение `group_id`, `domain_id` и `traffic_source_id` в локальной БД. Это избавляет фронтенд от хардкода и позволяет адаптировать приложение под конкретного пользователя.
4. **Современный UI:** Модальные окна, валидация ввода на лету (защита от нечисловых значений), адаптивная верстка и индикаторы загрузки.

---

## 🏗 Архитектурные решения

- **Зачем здесь SQLAlchemy?** В задании требовалось использовать FastAPI + SQLAlchemy. Вместо искусственного кэширования кампаний, я реализовал модель `UserSettings`. Это решает реальную бизнес-задачу: хранение дефолтных значений для пользователя, делая интерфейс гибким, а не захардкоженным.
- **Интеграция с Keitaro API:** Учтены специфические требования API Keitaro: использование поля `state` (вместо `status`), `traffic_source_id` (вместо `source_id`), корректные комбинации `schema` + `action_type`, а также раздельная загрузка метаданных кампании и её потоков (`streams`), так как основной эндпоинт GET не возвращает массив streams.
- **Стратегия тестирования:** Внешние вызовы к Keitaro полностью замокированы через `monkeypatch`. Тесты проверяют не только бизнес-логику, но и **точную структуру JSON-payload**, отправляемого в трекер. Это служит надежной регрессионной защитой от изменений в API Keitaro.

## 🚀 Быстрый старт

### 1. Подготовка окружения Backend

```bash
# Перейдите в папку backend
cd backend
```

#### Создайте и активируйте виртуальное окружение
```bash
python3 -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate
```

#### Установите зависимости
```bash
pip install -r requirements.txt
```

#### Создайте файл .env (скопируйте значения из вашей админки Keitaro)

```
KEITARO_URL=http://tlgk.host
KEITARO_API_KEY=ваш_ключ_api
DATABASE_URL=sqlite:///./local.db
```

### 2. Запуск Backend

``` bash
uvicorn app.main:app --reload
```

#### Сервер будет доступен по адресу: http://127.0.0.1:8000
#### Документация Swagger API: http://127.0.0.1:8000/docs

### 3. Подготовка и запуск Frontend

``` bash
# Откройте новый терминал и перейдите в папку frontend
cd frontend

# Установите зависимости
npm install

# Запустите dev-сервер
npm run dev
```
#### Приложение будет доступно по адресу: http://localhost:5173

## 🧪 Запуск тестов
### Все тесты изолированы, используют временную SQLite-базу и не отправляют реальные запросы в Keitaro.

``` bash
cd backend
source venv/bin/activate
python -m pytest
```

#### Ожидаемый результат: 12 passed за ~0.3 сек.

## 📝 Примечание для проверяющего

**При первом запуске Backend автоматически создаст файл `local.db`** с таблицей `user_settings` и дефолтными значениями (`group_id=1`, `domain_id=1`, `traffic_source_id=1`). 

Вы можете изменить эти значения через кнопку "⚙️ Настройки" в правом верхнем углу интерфейса приложения, и они будут автоматически применены ко всем новым создаваемым кампаниям и фильтру списка.
